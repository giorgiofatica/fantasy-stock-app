# Crests: something a manager earns and wears

Status: Draft (for Giorgio's approval). Not built.
Planner, 2026-11-25. Companion to
[`2026-11-25-onboarding-finish-and-feel.md`](2026-11-25-onboarding-finish-and-feel.md): that
plan is how onboarding moves; this one is what it ends on.

## Goal

A manager has a crest beside their name. The first one arrives as a surprise at the end of
onboarding, and a short list of others is earned by playing. Each one earned is a small
moment of its own.

## The shape he approved

1. **The first crest is a surprise.** On joining a first league, one crest from a starter
   set is revealed. Friends in the same league get different ones.
2. **A short list of earned crests**, about eight to start, each tied to something fantasy
   apps already celebrate.
3. **Every crest is visible from the first day.** Locked ones in grey, each with what earns
   it. Nothing hidden, nothing impossible to get.
4. **Each unlock gets its own reveal**, the next time the app is opened after it is earned.
5. **A manager wears one, and that is all anyone else sees.** The collection is private.
6. **Nothing to lose and nothing to buy.** No streak that can break, no tiers, no chance
   after the first crest.

Left out on purpose and told to him: tiers; and a champion's mark that cannot be taken off.

## The list, as a proposal

Placeholders. The list and every word are his to approve on the Design Lead's board.

| Crest | Earned when | Read from |
|---|---|---|
| A starter (one of about twelve) | You are first in a league, by joining one or creating one | league membership |
| First draft | A draft you took part in finishes | the draft's picks |
| First week won | A week of yours is scored as a win | scored matchups |
| Three wins in a row | Three scored weeks in a row are wins, in one league | scored matchups |
| Best week in the league | Your week is the best result of any manager in your league that week | scored matchups |
| Made the playoffs | Your league's playoffs are set and you are in them | the playoff matchups |
| Finished a season | A season of a league you are in is completed | the season's result |
| League champion | You win a league | the season's result |

Readings the Planner has made, to be checked against the code by the worker before
building:
- "First in a league" counts creating a league as well as joining one. The drawing said
  joining; a commissioner would otherwise have no crest.
- "Three wins in a row" is something that happened once, not a run to keep alive. Losing
  the fourth week takes nothing away.
- A tie for the best week gives the crest to each manager tied.
- Bots earn nothing and wear nothing.
- A crest belongs to the manager, not to a league. It is earned in a league and worn in
  every league.

## How it works

### What a manager sees

- **In onboarding.** On "You're in {league}", the first time only, the crest is revealed
  and then sits with the name. The same on "{name} is ready" for someone whose first
  league is one they created. A later league shows today's tick.
- **Joined on the web page first.** The crest is revealed the first time the app is opened.
- **Beside the name.** Wherever a manager's mark is drawn today (two initials on a disc,
  one shared component, about twenty places), the worn crest is drawn. The name stays
  where it is; the crest never replaces a name. A manager with no crest, a bot, and a
  deleted manager keep what they show today.
- **Earning one.** The next time the app is opened after a crest is earned, it is
  revealed, once. Two earned together are shown one after the other.
- **The collection, in Profile.** Held crests in colour, the worn one marked, locked ones
  in grey with what earns each. Tapping a held crest wears it.
- **Other people.** They see the crest you wear, beside your name, in leagues you share.
  Nothing else.

### What the server does

Read in the code on `main` at `8ad4d60c`.

- **A manager already has an "avatar" on the server**, which the app does not draw: a
  column on the profile (a default emoji from 2025), copied to `frozen_avatar` when a
  manager leaves a league, and empty for a deleted seat (`get_visible_profiles`,
  `20261119000000`, `20261125000001`). The worn crest takes that place, so leaving and
  deleting already do the right thing. The reads that name a manager for the app return
  the name only today; each also returns the worn crest, from the same shared helper the
  name comes from, so no screen can show a crest by a different rule than the name.
- **Awards are worked out from the record, not fired as events.** One function, given a
  league, reads what has been recorded (members, picks, scored weeks, playoffs, the
  season's result) and writes any crest a manager has earned and does not hold. It can
  be run again at any time and writes nothing twice. It is run after a week is scored,
  after a draft finishes, when playoffs are set and when a season completes; and a
  missed run is made good by the next one. This is the lesson this codebase has paid
  for five times: a thing granted once on an event is lost for good when that event
  half-fails.
- **The starter is picked on the server**, the first time a manager is in any league: at
  random from the starters nobody in that league holds yet, and from the whole set only
  when every one is taken. Chance alone would hand two friends the same crest often
  enough to notice. The app cannot choose it or ask again.
- **Nothing about crests can be written from the app except which one is worn**, and the
  database itself refuses a crest the manager does not hold. Today a manager can write
  any value into their own avatar column; that is closed in the same change.
- **A manager's collection is read by that manager only.** The reveal is driven by which
  held crests have not been shown yet, and showing one marks it shown.
- **Existing accounts** get a starter and whatever their recorded history has earned, by
  the same function, run once for every league.

### The reveal

The moment he liked in the other app. It is drawn by the Design Lead as a board that
moves, in two versions, in both themes and at his text size.

- It is a second or two, can be tapped through, and with Reduce Motion on the crest is
  simply there.
- The other app's box was a pre-made three-dimensional animation. The Researcher's reading
  of the two common libraries is that neither does true depth well; one of them is
  already bundled with our framework and the other needs its own build step and shows its
  maker's mark unless paid for. So the reveal is drawn flat with depth suggested, unless
  the Design Lead's board shows a reason to bring a library in.
- Touch: one tap on the phone as the crest lands. Sound is his call (below).

### The art

About twenty crests: twelve starters and eight earned (seven if the starter counts as
the first). The Design Lead proposes directions for his pick before any are drawn in
full. Each must read at the smallest size a mark is drawn today, in both themes, and for
someone who cannot tell colours apart. Drawn as vectors, which the app already supports.

## Scope

**In:** the starter and the list; the function that works awards out and the places it is
run; the worn crest travelling with the name; the collection in Profile; the reveal in
onboarding and on opening the app; existing accounts.

**Out:** tiers; a champion's mark; buying, trading or giving crests; anyone seeing another
manager's collection; photos or uploads; crests that differ by league; a push notification
for an earned crest (the reveal is on opening the app); the web join page.

## Risks

- **A crest granted to the wrong manager or missed.** Why awards are worked out from the
  record by one re-runnable function, per manager, and tested against a week that is half
  scored, a draft that is half made and a season that fails to complete once.
- **Scraping.** The worn crest is returned only where the name already is, to people who
  share a league. The collection is own-only. Both reviewers check the grants by what the
  database has, not by what the migration says.
- **A forged crest.** The app can say only which held crest is worn, and the database
  refuses anything else.
- **A crest someone dislikes.** The starter is chance. The second crest comes with the
  first draft, usually within days, so nobody is left with one they did not choose for long.
- **Marks that stop identifying people.** Two initials tell managers apart at a glance;
  twelve starters among ten friends may not. The Design Lead's board shows a full league
  of ten, and every place a mark is drawn with no name beside it.
- **The cost of the art.** Twenty drawings is the largest piece of this plan and the one
  most likely to slip. The first build may ship fewer earned crests; the locked ones
  shown must then be only ones that can be earned.

## Done means

1. A new manager who joins a first league by an invite link sees a crest revealed on
   "You're in", and it is beside their name on the league's screens afterwards.
2. Friends who join the same league get different starters, for as long as the league
   has fewer members than there are starters.
3. A manager whose week is scored as a win, and who then opens the app, sees one crest
   revealed, once; opening the app again shows nothing.
4. The awards function, run twice for the same league, writes nothing the second time;
   run after a week that scored only some matchups, then again when the rest are scored,
   it ends with every manager holding what they earned.
5. A manager cannot wear a crest they do not hold, tried from outside the app.
6. A manager in no shared league with another cannot read that person's worn crest; no
   one can read another's collection.
7. A manager who leaves a league is shown in its history with the crest they wore then;
   a deleted manager shows today's placeholder.
8. With Reduce Motion on, every reveal is the crest simply shown; checked in both themes
   at the largest text size.
9. `STATUS.md` records, by data, the first real crest earned from a scored week.
